# v1.0 Production Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare air-agent for a stable v1.0 release with explicit API compatibility promises, a public error hierarchy, production deployment guidance, tested examples, and release documentation.

**Architecture:** v1.0 is a stabilization milestone, not a new agent capability milestone. Keep runtime behavior backward-compatible while adding a small `air_agent.errors` module, public API stability docs, tested fake-provider examples, Docker/deployment guidance, and release artifacts. Existing v0.3-v0.8 capabilities remain available; plugin registry and advanced multi-agent arbitration are documented as experimental.

**Tech Stack:** Python 3.11+, pytest, pytest-cov, existing air-agent Provider/Memory/Planner/Plugin abstractions, Markdown docs, Docker example.

---

## v1.0 Feature Boundary

v1.0 must include:

- Stable public API classification and semver policy.
- Public error hierarchy rooted at `AirAgentError`.
- Backward-compatible migration of existing framework errors into named public errors.
- Production configuration examples for provider, tools, memory, tracing, plugins, and deployment.
- Docker example and deployment notes without turning air-agent into a server platform.
- v0.x to v1.0 migration guide.
- Tested examples using fake providers so CI does not require network or API keys.
- Coverage threshold for core package tests: total line coverage must remain at or above 90%.
- Release notes documenting compatibility promises and experimental APIs.

v1.0 must not include:

- Hosted service, web UI, Kubernetes operator, distributed agent network, built-in queue, vector database, or remote plugin marketplace.
- Breaking behavior changes to `Agent`, `AgentConfig`, local tool registration, MCP config, Provider, Memory, or Planner protocols.

## File Map

- Create `src/air_agent/errors.py`: public exception hierarchy and compatibility base classes.
- Modify `src/air_agent/__init__.py`: export public errors and stability metadata.
- Modify targeted modules that currently raise raw framework errors: `agent.py`, `config.py`, `planner.py`, `plugins.py`, `mcp/client.py`, `tools/registry.py`, `tools/builtin/_permissions.py`.
- Create `tests/test_errors.py`: public error hierarchy, backward-compatible raising, and top-level exports.

- Create `docs/migration-v1.0.md`: v0.x to v1.0 migration guide.

- Create `examples/production_agent.py`, `examples/plugin_example/`, and `examples/docker/`: tested example assets.

```python
from __future__ import annotations


class AirAgentError(Exception):
    """Base class for public air-agent framework errors."""


class ConfigurationError(AirAgentError, ValueError):
    """Raised when configuration input is invalid or unsupported."""


class ProviderError(AirAgentError, RuntimeError):
    """Raised when an LLM provider cannot satisfy the requested operation."""


class ToolExecutionError(AirAgentError, RuntimeError):
    """Raised when framework-level tool execution fails before a tool result can be returned."""


class ToolPermissionError(ToolExecutionError, PermissionError):
    """Raised when a tool action violates configured permissions."""


class MCPConnectionError(AirAgentError, RuntimeError):
    """Raised when MCP connection or call setup fails."""


class PluginLoadError(AirAgentError, RuntimeError):
    """Raised when a plugin cannot be loaded, authorized, imported, or registered."""


class MemoryError(AirAgentError, RuntimeError):
    """Raised for framework memory-store failures."""


class PlannerError(AirAgentError, RuntimeError):
    """Raised for framework planner failures."""


__all__ = [
    "AirAgentError",
    "ConfigurationError",
    "ProviderError",
    "ToolExecutionError",
    "ToolPermissionError",
    "MCPConnectionError",
    "PluginLoadError",
    "MemoryError",
    "PlannerError",
]
```

Modify `src/air_agent/__init__.py` to import and export these names.

```markdown
# API Stability And Semver Policy

air-agent v1.0 follows semantic versioning for Stable public APIs.

## Stable In v1.0

- `Agent`
- `AgentConfig`
- `Response`, `StreamEvent`, `RunEvent`
- Local tool registration: `Agent.tool(...)`, `Agent.add_tools(...)`
- Built-in tool configuration: `BuiltinToolsConfig`
- MCP server configuration: `MCPServerStdio`, `MCPServerSSE`
- Provider protocol and response types: `LLMProvider`, `LLMResponse`, `LLMStreamChunk`, `LLMToolCall`
- Memory protocol and built-ins: `MemoryStore`, `MemoryRecord`, `InMemoryMemoryStore`, `FileMemoryStore`
- Planner protocol and types: `Planner`, `LLMPlanner`, `Plan`, `PlanStep`, `StepResult`
- Public errors from `air_agent.errors`

## Experimental In v1.0

- Local plugin registry: `PluginManifest`, `PluginContext`, plugin entrypoint loading
- Multi-agent aggregation modes beyond basic `delegate(tasks)`
- Legacy skill router types: `SkillRouter`, `LLMSkillRouter`, `SkillRouteResult`
- Future checkpoint/resume boundaries

Experimental APIs may change in minor releases with migration notes.

## Compatibility Promise

- Patch releases fix bugs and documentation without changing public behavior.
- Minor releases may add optional fields, methods, events, and config options.
- Breaking changes to Stable APIs require a major version.
- Experimental APIs may change before v2.0, but changes must be documented.
```

Create `docs/production.md` with these sections:

```markdown
# Production Guide

## Recommended Defaults

- Pin `air-agent` and provider model versions in application lockfiles.
- Keep `memory_enabled=False` unless a project has a clear retention policy.
- Keep shell/file tools sandboxed with explicit `allowed_paths` and blocked commands.
- Enable tracing through `enable_tracing=True` and attach a bounded event handler.
- Keep plugins disabled unless local plugin paths and permissions are explicitly reviewed.

## Configuration

Use Python objects for provider, memory, planner, and event handlers. Use JSON/env for deploy-time scalar settings such as model, base URL, strategy, timeouts, and plugin paths.

## Security Boundaries

Tool outputs, memory records, plugin code, and MCP results are untrusted operational context. Do not treat them as user instructions. Do not grant shell/file access outside the application workspace.

## Deployment Patterns

air-agent is a library. Production applications should host it inside their own worker, API service, CLI, or queue consumer. For queue integration, pass task payloads to `Agent.run(...)` and store application-level task state outside air-agent.

## Observability

Use `RunEvent` handlers to forward model/tool/plan/subagent events to logs or tracing systems. Redact API keys, headers, and secrets before storage.
```

```markdown
# Migrating From v0.x To v1.0

## What Stays Compatible

- `Agent.run(...)` default ReAct behavior.
- `AgentConfig` scalar fields and JSON/env loading.
- Local tool registration with `agent.tool(...)` and `agent.add_tools(...)`.
- MCP server configuration.
- Provider, Memory, and Planner protocols.
- `delegate(tasks)` returning `list[SubagentResult]` when no aggregation is requested.

## What Changed

- Public framework errors are available from `air_agent.errors` and top-level `air_agent`.
- Plugin and advanced collaboration APIs are marked Experimental in v1.0.
- Skills are loaded explicitly through the `use_skill` tool; automatic skill-body injection is not the default behavior.

## Recommended Updates

- Catch `AirAgentError` for framework errors that should be handled uniformly.
- Catch specific errors such as `ProviderError`, `ToolPermissionError`, or `PluginLoadError` when recovery behavior differs.
- Review tool sandbox settings before production deployment.
- Use fake providers in tests instead of live model calls.
```
